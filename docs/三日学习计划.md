# C8 RAG 项目三日学习计划（面试导向）

> **目标**：三天后能完整讲清项目流程、每个设计决策的 why，扛住面试官深挖。
> **方法**：自顶向下——先思想/数据流，再状态转变，只对"体现设计决策"的函数逐行精读。

## 使用说明：什么叫精读，什么叫粗读

判断标准只有两条：

1. **体现设计决策的代码 → 精读**：切块策略、RRF 融合、权限下推、父子回溯、Agent 状态机、兜底链——所有面试官会追问 "why" 的地方，逐行读，读到自己能复述"为什么不用别的方案"。
2. **数据结构定义 → 记住**：schema、AgentState、manifest 字段——面试要能脱口而出里面有什么。
3. **其余一切 → 粗读/跳读**：与第三方 API 打交道的参数细节、防御性样板、日志/异常处理、manifest 读写工具函数——知道"它存在、解决什么"即可，**永远不背 API 参数**。

精读时用**费曼复述**：每读完一个函数，合上代码，用自己的话讲一遍"它做什么、为什么这样写、换我会怎么写"。讲不顺就回去重读。

每天节奏建议 6~8 小时，上午/下午各一段，晚上 30 分钟自测。
