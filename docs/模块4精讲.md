# 模块四：agentic_rag.py 逐行精讲（LangGraph Agent）

> 本文是 `CODE_WALKTHROUGH.md` 的续篇（模块一~三见彼文）。
> **解决什么**：把检索栈包装成工具，让 LLM 自主决定"调哪个工具、传什么参数、结果不好怎么办"，
> 并在每个环节兜底。这是全项目进阶含量最高的模块。

---

## 4.1 State：Agent 的记忆体（逐字段）

```python
class AgentState(TypedDict, total=False):   # ① total=False：所有字段可选
    question: str                           # ② 用户当前问题（只读）
    role: str                               # ③ 权限角色（只读）
    history: list[dict[str, Any]]           # ④ 多轮历史 [{"role":"user","content":...}]
    messages: Annotated[list[Any], add_messages]   # ⑤ LangGraph内置reducer（本项目未用，留扩展）
    route: str                              # ⑥ 当前选择的工具名
    tool_args: dict[str, Any]               # ⑦ LLM 抽取的工具参数
    chunks: list[Document]                  # ⑧ 检索命中的子块
    parents: list[Document]                 # ⑨ 回溯出的父文档（生成的上下文）
    image_paths: list[str]                  # ⑩ 命中的图片路径
    answer: str                             # ⑪ 最终回答；非 None 表示"已有答案，可短路"
    rewrites_used: int                      # ⑫ 已用改写次数（防无限重试）
    retry_pending: bool                     # ⑬ "reflect 已准备好改写，等 act 重试"标志
    error: str | None                       # ⑭ 降级原因（不中断流程，最后落trace）
    events: list[dict[str, Any]]            # ⑮ 审计事件流（Day5 追踪的数据源）
```

- **▶ ① 为什么 total=False**：图从 `{question, role, history, rewrites_used, events}` 起步，
  其余字段随节点执行逐步出现。每个节点只读自己需要的、只写自己负责的。
- **▶ ⑪ answer 是"短路开关"**：direct_answer 和离线兜底直接写 answer，
  后续节点看到 answer 非 None 就原样返回——用数据状态代替控制流分支。
- **▶ ⑬ retry_pending 的存在是因为 LangGraph 的条件边只能"读状态做决策"不能传参**，
  reflect 想告诉 act"这次带新 query 来"只能通过状态传话（这个设计踩过死循环坑，见 4.7）。

## 4.2 `build_agent_tools`：工具说明书工厂

```python
def build_agent_tools(domain: DomainConfig | None = None) -> list[dict[str, Any]]:
    domain = domain or get_domain()
    descriptions = domain.tool_descriptions     # ① 描述文本来自领域配置（换领域自动换）
    categories = domain.category_labels         # ② 枚举也来自领域配置
    difficulties = list(domain.difficulty_labels)
    return [
        {
            "type": "function",
            "function": {
                "name": "search_recipes",
                "description": descriptions["search_recipes"],
                "parameters": {
                    "type": "object",
                    "properties": {
                        "query": {"type": "string",
                                  "description": descriptions["query_param_example"]},
                        #            ▶ 参数描述里的示例（"如'红烧肉怎么做'"）教会LLM怎么改写查询
                        "category": {"type": "string", "enum": categories, ...},
                        #            ▶ enum 硬约束：LLM 只能从真实分类里选，幻觉"川菜"直接被拒
                        "difficulty": {"type": "string", "enum": difficulties, ...},
                    },
                    "required": ["query"],
                },
            },
        },
        # ... search_images / list_by_metadata / direct_answer 同构
    ]
```

**工具选择的四层约束**（本模块安全设计的骨架）：
1. **description 语义引导**——写得越准，选得越对（软约束）；
2. **enum/schema 硬约束**——参数值域锁死（中约束）；
3. **代码校验兜底**——路由返回不合法时降级默认检索（硬兜底）；
4. **图结构限轨迹**——节点/边写死、递归上限 8，LLM 只能在轨道里选（硬边界）。

## 4.3 历史注入的两个工具函数

```python
@staticmethod
def _history_messages(history, *, limit=6) -> list[dict]:
    """路由用：历史作为标准 chat messages 插入（LLM 原生理解对话结构）"""
    if not history: return []
    return [{"role": t["role"], "content": str(t["content"])}
            for t in history[-limit:]                      # ① 只取最近6条消息=3轮
            if t.get("role") in {"user", "assistant"} and t.get("content")]  # ② 脏数据过滤

@staticmethod
def _history_prefix(history, *, limit=4) -> str:
    """生成用：历史压缩成文本前缀拼在问题前"""
    if not history: return ""
    lines = [f"{'用户' if t['role']=='user' else '助手'}: {str(t['content'])[:120]}"
             for t in history[-limit:]]
    #            ▶ 每条截断120字：历史只是理解指代的线索，不值得占满上下文
    return "（对话历史，供理解指代用，回答只针对当前问题）\n" + "\n".join(lines) + "\n\n当前问题: "
```

- **▶ 为什么两个函数而不是一个**：路由走 messages 列表（function calling 模型按角色理解），
  生成走文本拼接（basic_answer_prompt 只有 {question} 占位符）——**同一个信息，两种消费格式**。

## 4.4 `_route_llm_call`：function calling 的发起与防御（逐行）

```python
def _route_llm_call(self, question, history=None):
    messages = [
        {"role": "system", "content": self.domain.agent_router_prompt},  # ① 路由规则（领域配置）
        *self._history_messages(history),                                # ② 历史消息
        {"role": "user", "content": question},                           # ③ 当前问题
    ]
    message = self._llm().bind_tools(self.tools).invoke(messages)
    #        ▶ ④ bind_tools：把工具schema附到这次请求；模型"知道有哪些工具可调"
    tool_calls = getattr(message, "tool_calls", None) or []   # ⑤ 防御：属性可能不存在/为None
    if tool_calls:
        call = tool_calls[0]                                   # ⑥ 只取第一个（单工具调用设计）
        return {"route": call["name"], "tool_args": dict(call["args"])}
    if content := str(message.content or "").strip():          # ⑦ 没调工具但说话了→当直接回答
        return {"route": "direct_answer", "tool_args": {"answer": content}}
    raise ValueError("路由 LLM 未返回工具调用")                  # ⑧ 两者皆无→异常（上层兜底）
```

- **▶ ⑦⑧ 是完备性处理**：LLM 的输出有三种可能——调工具/纯文本/啥也没有。
  前两种有语义，第三种只能抛给上层降级。**穷举输出可能性是写 Agent 的基本功**。

`_route_node` 包一层防御：
```python
try:
    decision = self._route_llm_call(question, history=state.get("history"))
except Exception as exc:
    logger.warning("路由节点失败，降级为默认检索: %s", exc)
    decision = {"route": "search_recipes", "tool_args": {"query": question}}  # 拿原问题检索
    state["error"] = f"route_fallback: {exc}"     # 降级原因入state→最终落trace
```

## 4.5 `_act_node`：工具分派 + 二级兜底（核心 40 行）

```python
def _act_node(self, state):
    state["retry_pending"] = False               # ▶ ① 显式覆盖（LangGraph合并语义，见4.7）
    route = state.get("route", "search_recipes")
    args = state.get("tool_args", {})
    role = state.get("role", "user")
    question = state["question"]
    state["chunks"] = []; state["parents"] = []; state["image_paths"] = []   # ② 清空重试残留

    if route == "direct_answer":                 # ③ 闲聊短路：不检索直接出答案
        state["answer"] = str(args.get("answer","")).strip() or self.domain.direct_answer_default
        return state

    try:
        if route == "search_images":             # ④ 图搜：modality过滤+可见性
            chunks = self.retrieval_module.metadata_filtered_search(
                args.get("query", question), {"modality": "image"},
                top_k=self.top_k, extra_expr=self._visibility_expr(role))
        elif route == "list_by_metadata":        # ⑤ 浏览：过滤条件即查询词
            filters = {k: v for k, v in args.items() if v}
            query = " ".join(str(v) for v in filters.values()) or "家常菜谱推荐"
            chunks = self.retrieval_module.metadata_filtered_search(
                query, filters, top_k=max(self.top_k,5),
                extra_expr=self._visibility_expr(role))
        else:                                    # ⑥ 默认=search_recipes
            chunks = self._search_recipes(args.get("query", question), role,
                                          **{k: args.get(k) for k in ("category","difficulty")})
    except Exception as exc:                     # ▶ ⑦ 二级兜底：工具炸→退回混合检索
        state["error"] = f"tool_fallback({route}): {exc}"
        try:
            chunks = self.retrieval_module.hybrid_search(
                question, top_k=self.top_k, expr=self._visibility_expr(role))
        except Exception:                        # ⑧ 三级兜底：检索也炸→离线回答
            state["answer"] = self._offline_answer(question)
            state["error"] = "retrieval_unavailable"
            return state

    parents = self.data_module.get_parent_documents(chunks) if chunks else []   # ⑨ 父文档回溯
    state["chunks"] = chunks; state["parents"] = parents
    for chunk in chunks:                          # ⑩ 收集图片路径（去重截6条）
        if chunk.metadata.get("modality") == "image" and chunk.metadata.get("image_path"):
            ...
    return state
```

- **▶ ② 每次进 act 都清结果**：改写重试会第二次进入 act，不清空的话上次失败残留会污染判断。
- **▶ ⑤ list_by_metadata 的 query 构造**："汤品 简单"（过滤值拼成查询串）——
  向量检索需要一个查询串，用过滤值本身是最诚实的信号。
- **▶ ⑦⑧ 兜底的层次感**：工具失败≠检索失败≠系统失败，逐级降而非一刀切 try/except 返回错误。

## 4.6 `_reflect_node`：反思与改写

```python
def _reflect_node(self, state):
    if state.get("answer") is not None:           # ① 短路：已有答案（闲聊/离线兜底）直接过
        return state
    rewrites_used = state.get("rewrites_used", 0)
    if not state.get("chunks") and rewrites_used < MAX_REWRITES:   # ② 空结果且还有改写额度
        try:
            rewritten = self._rewrite_query(state["question"], history=state.get("history"))
        except Exception as exc:
            state["rewrites_used"] = MAX_REWRITES  # ▶ ③ 改写失败=烧掉额度，防止下轮再试死循环
            return state
        state["rewrites_used"] = rewrites_used + 1
        state["route"] = "search_recipes"
        state["tool_args"] = {"query": rewritten}   # ④ 换弹药
        state["retry_pending"] = True               # ⑤ 通知条件边"回act"
        return state
    if not state.get("parents"):                    # ⑥ 彻底没结果→记事件（generate负责拒答）
        state.setdefault("events", []).append(_event("no_results"))
    return state
```

- **▶ ③ 冷门但关键**：改写 LLM 挂了，如果不消耗额度，下次 reflect 又会尝试改写→再挂→
  下下轮……直到递归上限。**失败也要消耗资源计数**是防循环的通用手法。

## 4.7 `_decide_after_reflect` + 死循环大坑

```python
def _decide_after_reflect(self, state) -> str:
    if state.get("answer") is not None: return END        # ① 有答案→结束
    if state.get("retry_pending"): return "act"           # ② reflect备好了改写→回去重试
    if not state.get("chunks"): return "generate"         # ③ 没结果且没改写额度→去拒答
    return "generate"                                     # ④ 正常→去生成
```

**死循环事故复盘（必背）**：
- 现象：改写重试后无限循环直到 `GraphRecursionError: recursion limit of 8`。
- 根因：LangGraph 节点返回的 dict 是**增量合并**——返回里**缺省的 key 保留旧值**。
  在 act 里 `state.pop("retry_pending")` 看似删了，但 state channel 里旧值 `True` 还在，
  条件边永远走"回 act"。
- 修复：act 开头 `state["retry_pending"] = False`——**清除也必须是显式写入**。
- 通用教训：声明式状态框架（LangGraph/React）里，"删除状态"和"设置状态"不是一回事。

## 4.8 `_generate_node`：生成 + 四级兜底收口

```python
def _generate_node(self, state):
    if state.get("answer") is not None: return state       # ① 短路
    parents = state.get("parents", [])
    question = self._history_prefix(state.get("history")) + state["question"]
    #            ▶ ② 多轮：历史前缀+当前问题拼成生成问题（指代有上下文可解）
    if not parents:
        state["answer"] = self.domain.agent_no_results      # ③ 拒答话术（领域配置）
        return state
    try:
        state["answer"] = self.generation_module.generate_basic_answer(
            question, parents, image_paths=state.get("image_paths"))
    except Exception as exc:                                # ④ 四级兜底：LLM挂→规则摘要
        state["answer"] = self._offline_answer(question, parents)
        state["error"] = f"generate_fallback: {exc}"
    return state
```

- **▶ ③ 拒答也是能力**：客服场景"诚实说没有"远好于硬编。拒答话术放领域配置，可按领域定制。

## 4.9 `_build_graph` + `invoke`：组装与入口

```python
def _build_graph(self):
    graph = StateGraph(AgentState)
    graph.add_node("route",    self._route_node)
    graph.add_node("act",      self._act_node)
    graph.add_node("reflect",  self._reflect_node)
    graph.add_node("generate", self._generate_node)
    graph.add_edge(START, "route")                          # 固定边：起点→路由
    graph.add_edge("route", "act")                          # 路由必进执行
    graph.add_edge("act", "reflect")                        # 执行必进反思
    graph.add_conditional_edges("reflect", self._decide_after_reflect,
                                {"act": "act", "generate": "generate", END: END})
    #            ▶ 唯一的"岔路口"：反思之后才有可能回头或直达终点
    graph.add_edge("generate", END)
    return graph.compile()

def invoke(self, question, *, role="user", history=None) -> dict:
    initial = {"question": question, "role": role, "history": history or [],
               "rewrites_used": 0, "events": []}
    result = self.graph.invoke(initial, config={"recursion_limit": 8})
    #            ▶ 递归上限：第二重防死循环保险（第一重是 rewrites_used 额度）
    return result
```

- **▶ history 由调用方维护**（CLI 循环 / API session），agent 自身无状态——无状态才好水平扩容，
  会话状态外置是服务设计的标准姿势。

**本模块一句话**：Agent = 状态机 + 工具 + 兜底；LLM 只做"选择"，**可靠性全部由代码层的不变量保证**
（额度计数、显式覆盖、递归上限、四级降级）。面试时能讲清 retry_pending 死循环复盘，胜过背十个概念。
