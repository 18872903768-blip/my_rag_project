## 5.2 `_matches`：什么算"命中"

```python
def _matches(expected: str, dish_name: str) -> bool:
    return expected in dish_name or dish_name in expected
    # 子串双向匹配："红烧肉" 匹配 "简易红烧肉"（期望名是返回名的子串）也匹配反向情形
```

- **▶ 为什么不是全等**：golden set 期望写"红烧肉"（人工标注的自然写法），
  库里菜名是"简易红烧肉/湖南家常红烧肉"——全等会把正确结果误判为 miss。
  代价：粒度略粗，但符合"人怎么判断答对了"的直觉。

## 5.3 `evaluate_item`：单条评测的三种判定逻辑（核心函数逐行）

```python
def evaluate_item(system, item, top_k):
    results = system.retrieve(item["query"], top_k=top_k, role=item.get("role", "user"))
    #            ▶ ① 用被测系统自己的 retrieve（含权限链路）——测的是真实用户路径
    returned = [{"dish": ..., "visibility": ..., "category": ..., "difficulty": ...}
                for doc in results]                   # ② 把需要的元数据抽出来快照
    record = {"query": ..., "role": ..., "intent": ..., "returned": [...], "expected": [...]}

    if item.get("expect_empty"):                      # ===== 分支A：权限类 =====
        record["leaks"] = [r["dish"] for r in returned if r["visibility"] == "internal"]
        #            ▶ 泄漏定义=返回了internal条目；返回公开菜谱不算（那是设计好的降级）
        record["hit"] = not record["leaks"]
        return record

    if item.get("expected_filters"):                  # ===== 分支B：浏览类 =====
        filters = item["expected_filters"]
        violating = [r["dish"] for r in returned
                     if (filters.get("category") and r["category"] != filters["category"])
                     or (filters.get("difficulty") and r["difficulty"] != filters["difficulty"])]
        #            ▶ 过滤精确率：返回的每一条都必须符合期望的分类/难度
        record["hit"] = bool(returned) and not violating   # 有结果 且 零违规
        return record

    # ===== 分支C：detail/keyword 类（排名敏感）=====
    ranks = []
    for dish in expected:                             # ① 对每个期望菜名
        for rank, returned_dish in enumerate(returned_dishes, start=1):
            if _matches(dish, returned_dish):
                ranks.append(rank)                    # ② 记录它第一次出现的位置
                break
    record["hit"] = bool(ranks)                       # ③ Hit@k：进前k即1
    record["reciprocal_rank"] = 1.0 / min(ranks) if ranks else 0.0   # ▶ MRR原料：1/最优排名
    record["recall"] = len(ranks) / len(expected) if expected else 0.0  # ④ 期望集覆盖率
    return record
```

- **▶ 分支A的判定演进史（面试好素材）**：最初版本把"返回任何结果"都算泄漏——
  实测发现 user 查"速冻水饺工艺"返回了公开的"手工水饺"，这是**设计好的优雅降级**不是泄漏。
  于是修正定义为"返回 internal 才算"。**评测标准本身也需要被审视**。
- **▶ 分支B为什么不用排名指标**："推荐几道简单的汤"命中哪道汤都对——
  浏览类查询的正确性是"过滤是否精确"，不是"排序是否第一"。**指标要贴意图**。
- **▶ reciprocal_rank 是 MRR 的原子**：MRR = 全体 reciprocal_rank 的平均（见 5.4）。

## 5.4 聚合与报告：`_metric` + by_intent

```python
by_intent: dict[str, list[dict]] = {}
for record in records:
    by_intent.setdefault(record["intent"], []).append(record)   # ① 按意图分桶

def _metric(rows, key) -> float:
    return statistics.mean(row[key] for row in rows) if rows else 0.0   # ② 简单平均

for intent, rows in sorted(by_intent.items()):
    summary_rows.append({"intent": intent, "count": len(rows),
                         "hit_rate": round(_metric(rows, "hit"), 4),
                         "mrr": round(_metric(rows, "reciprocal_rank"), 4),
                         "recall": round(_metric(rows, "recall"), 4)})
```

- **▶ ① 分桶的意义**：总体指标会撒谎——0.90 的总 MRR 可能是"detail 满分 + browse 零分"
  拼出来的。按意图拆开才能定位"哪类查询坏了"（本项目的重排实验正是靠分桶发现
  detail 掉分、其他持平，才定位到"CE 干扰精确名匹配"）。
- **② MRR 手算**：3 条查询的 reciprocal_rank 分别为 1、0.5、0.2 → MRR=(1+0.5+0.2)/3≈0.567。

  badcase 分析时不用重跑，直接翻 JSON。

## 5.6 用这套评测做过的一次真实决策（重排实验流程）

1. 基线：`RAG_RERANK_ENABLED=false` 跑一次 → MRR 0.931 存档；
2. 实现：纯 CE 定序跑一次 → 0.879（**掉点了**）；
3. 假设修正：CE 与召回序二次 RRF 融合再跑 → 0.902（仍低于基线）；
4. 归因：分桶看 detail 掉分 → 精确菜名查询被 CE 的语义偏好干扰；
5. 决策：默认关闭、保留开关、数字写进 README 和配置注释。

**这五步（假设→实现→测量→归因→决策）就是评测体系的全部意义。**

**本模块一句话**：评测脚本本身很简单（不到200行），难的是**指标贴意图**（三种判定逻辑）
和**把评测当决策工具而非汇报工具**。
